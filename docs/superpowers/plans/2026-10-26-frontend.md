# MatchMind Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the MatchMind website: a fan's personalized AI pundit beside a live synthetic match, in the club's colors, with Ask why, a live re-ask, and a Best Plays tab.

**Architecture:** A Vite + React + TypeScript single-page app in `web/`, talking only to the TASK-21 API (`wiki/api-frontend.md`) through a typed client. Zustand holds preferences (persisted to `localStorage`) and live playback state; the pitch is a canvas that interpolates 5 Hz SSE frames to 60 fps. The club theme is computed at runtime from the club's two colors into CSS variables so every club passes WCAG AA.

**Tech Stack:** React 18.3, Vite 5, TypeScript 5.6, Tailwind CSS 3.4, Zustand 5, visx 3, Vitest 2 + Testing Library 16 (jsdom), Playwright 1.48 + @axe-core/playwright 4.10. Node 22.

**Spec:** `docs/superpowers/specs/2026-10-26-frontend-visual-direction-design.md` (argues from the original plan's Task 22 and 23 in `docs/superpowers/plans/2026-10-21-matchmind.md`).

## Global Constraints

- Stack: React + Vite + TypeScript + Tailwind; Zustand; visx; Vitest, Playwright, axe-core. Anything else goes on the Adopt list in `docs/research/open-source-review.md` first (Testing Library and jsdom are added in Task 1).
- WCAG 2.1 AA contrast under every club's colors, full keyboard use, usable at 375 px wide (Constitution).
- Languages `en`, `es`, `pt`, `fr`, `ar`; `dir="rtl"` on `<html>` when `lang === "ar"`.
- Data comes only from the TASK-21 API; the one allowed API addition is `best_play_event_id` on the insights list (Task 6).
- No real clubs, players, or organizations: no Premier League colors, lion, fonts, logos, or copied layouts. Fonts are open-licensed (Google Fonts).
- Prefs in `localStorage`, every access in try/catch: `{mode: "fan" | "scout", focus: "team" | "player", lang, favorite_club_id, favorite_player_id, sides: {[match_id]: club_id}}`.
- Direction: broadcast-dark (`docs/design.md`). The view switches are two-position toggles, Team ⇄ Player and Fan ⇄ Scout, plus a language menu.
- Every commit updates `wiki/` (at least `wiki/api-frontend.md` and `wiki/changelog.md`); messages start with `TASK-N.M:` and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `TASKS.md` stays untracked.
- Use the frontend-design skill for the mockups (Task 2) and for every component's styling.

## Review Focus

1. **A club whose primary color is very light or very dark** (El Prado `#FFD700`, Chipre `#000000`, Chapinero `#FFFFFF` secondary): text and cards stay AA-readable. Pinned by `theme.test.ts` over all 20 clubs (Task 1).
2. **The SSE connection drops or the viewer seeks:** no duplicated or lost insight cards. Pinned by `live.test.ts` "dedupes by seq and insight_id" (Task 4).
3. **Arabic:** text flips right to left, but the pitch, timeline, and charts must not mirror (x is the physical pitch). Pinned by `rtl.test.tsx` (Task 7).
4. **`localStorage` throws** (private mode, blocked storage): the app still loads with defaults. Pinned by `prefs.test.ts` (Task 3).
5. **The favorite player isn't in this match, or the live re-ask hits its limit:** Scout falls back to `analyst`; a 429 shows the wait, and a double click sends one request. Pinned by `persona.test.ts` (Task 7) and `AskWhyPanel.test.tsx` (Task 6).

### Task 4 (TASK-23.2): Live stream, animated pitch, and playback controls

**Files:**
- Create: `src/live/stream.ts`, `src/live/interpolate.ts`, `src/components/Pitch.tsx`, `src/components/PlaybackBar.tsx`, tests `live.test.ts`, `interpolate.test.ts`, `PlaybackBar.test.tsx`

**Interfaces:**
- Consumes: the SSE contract (`GET /api/matches/{id}/live?period&from_t&speed`; events `frame | event | cue | insight | end`; ids `"{period}:{t}:{seq}"`).
- Produces in `stream.ts`: `openLive(matchId, {period, from_t, speed}, handlers: {frame, event, cue, insight, end, status}): {close(): void}` using `EventSource`. Every reconnect sends `Last-Event-ID` (the browser does this itself). It drops any message whose `seq` is ≤ the last seen, and any `insight` whose `insight_id` it has already delivered in this session.
- Produces in `interpolate.ts`: `interpolate(a: Frame, b: Frame, t: number): Frame`, linear on x and y per `player_id` (players present in only one frame are drawn as they are), and `clockOf(period, t, firstHalfS)`.
- Produces in the store: `seek(period, t)` (closes and reopens with `from_t`), `play()`, `pause()` (close; remember t), `setSpeed(s)` (reopen at the current t), with speeds `[0.5, 1, 2, 4, 8]`.

- [ ] **Step 1: Write the failing tests:**
  - `interpolate.test.ts`: halfway between frames at t=10.0 and t=10.2, a player at x 10 → 12 is at 11. A player missing from frame b stays at their position in a.
  - `live.test.ts` (with a fake `EventSource`): a replayed message with an equal or lower `seq` is ignored; "dedupes by seq and insight_id" (the same insight id at a new seq after a seek is delivered once per session); `end` calls `end` and closes.
  - `PlaybackBar.test.tsx`: Space toggles play and pause; choosing 2× calls `setSpeed(2)`; the seek slider calls `seek` with the period and t; every control is reachable by Tab and has a label.
- [ ] **Step 2: Run** `npm test`. Expected: FAIL.
- [ ] **Step 3: Implement.** `Pitch.tsx` draws on a canvas (105 × 68 m scaled, `devicePixelRatio`-aware) in a `requestAnimationFrame` loop. It renders 200 ms behind the newest frame, interpolating between the two frames around that time, so 5 Hz looks smooth at 60 fps. Home players use `--mm-home` and away players `--mm-away` (with a contrasting outline); the ball is white with a shadow. The canvas wrapper is `dir="ltr"`.
- [ ] **Step 4: Run** `npm test`. Then open a match against the local API (`uv run uvicorn matchmind.api.app:app` plus `npm run dev`) and check smooth motion with the browser's performance panel showing frames at about 60 fps. Expected: PASS and smooth.
