# MatchMind Constitution

**Version:** 1.0.0 · **Ratified:** 2026-10-21 · **Owner:** @sebz04 (solo entrant)

MatchMind turns synthetic football events into explainable, personalized match intelligence for the Microsoft Premier League Hackathon. This constitution sets the non-negotiable rules every spec, plan, task, and pull request must follow. Where a plan or task conflicts with it, the constitution wins.

**Hard deadline:** submission closes **2026-10-27, 11:59 pm Pacific Time**. The demo must stay live and free to judges until **2026-11-10, 11:59 pm PT**.

---

## Core Principles

### I. Code computes, agents interpret (NON-NEGOTIABLE)
Every number shown to a user is computed by deterministic Python or SQL and stored in the stats store. Foundry agents may select, explain, narrate, translate, and personalize. They may never invent a figure. Agents get numbers only through the MCP stats server.

### II. Verified before visible (NON-NEGOTIABLE)
No agent text reaches the screen until the Verifier passes it. Every claim carries the event IDs and metric it rests on, plus a confidence label (`high` / `medium` / `low`). Translated text is verified again in its own language. If a claim still fails after the retry limit, a deterministic template takes its place, so the screen is never blank and never wrong.

### III. Synthetic and fictional, end to end
- All match, tracking, and season data is generated by our own seeded engine. No real event or tracking data is used to train or tune any model shipped in the product.
- Clubs, players, stadiums, crests, and the league are fictional. No Premier League, club, or broadcaster names, logos, or trademarks appear in the product, repo, or video.
- Open-source dependencies are used under their licenses and are extended, not merely re-skinned. Each one is credited in the README.
- The demo video uses only royalty-free audio and our own footage.

### IV. Reproducible by seed
The same seed and scenario always produce the same match. Tests and CI never call a live model: they use a fake chat client and recorded fixtures. Every precomputed replay records the seed, engine version, model deployment, and prompt version that produced it.

### V. Test-first, always green
New behavior starts with a failing test (TDD). `main` stays green on CI: lint (ruff), types (mypy on `src/`), unit tests (pytest), frontend tests (Vitest), and a Playwright smoke test. A task is not done until its acceptance criteria are met and committed under its task ID (see `TASKS.md`).

### VI. Microsoft-first, and lean
- The app reaches models only through **Microsoft Foundry** deployments, orchestrated with **Microsoft Agent Framework**. It never calls OpenAI or Anthropic APIs directly.
- Core platform: Foundry, Agent Framework, MCP, Azure SQL Database, Azure Blob Storage, Azure Container Apps, Azure Static Web Apps, Application Insights, GitHub Actions.
- Each extra service (Event Hubs, Functions, Web PubSub, Speech, Translator) must make a visible difference in the demo before it is added, and is added only after the core pipeline is finished.

### VII. Live-ready by design
Two lanes:
- **Fast lane:** deterministic overlays (name tags, speed and distance alerts, stat cards) render within **1 s** of their event.
- **Insight lane:** verified agent insights arrive within **10 s** of their moment during live replay.

Judges see precomputed replays by default. Live regeneration is opt-in and rate-limited.

### VIII. Agents with distinct jobs
Each agent has one role, one prompt file, one typed output schema, and one owner in the workflow. Agents coordinate through shared state in the stats store and explicit handoffs, not hidden conversations. Every run writes a trace to Application Insights that the "Ask why" panel can show. If a single prompt could do an agent's job just as well, that agent does not exist.

### IX. Secure in public
The repository is public. Secrets live only in `.env` (git-ignored) locally and in managed identity or Container Apps secrets in Azure. The app collects no personal data. User preferences are anonymous and kept per browser.

### X. Polish over breadth
First the core pipeline is made to look and work perfectly: generator → stats → Analyst → Explainer → Verifier → Narrative/Personalization → UI. The phase-two agents (Scenario Designer, Ingest, Overlay Director) and the extra services come after it. A polished, working feature always beats two rough ones.

### XI. Every fan, every market
- The same insight is offered in four personas: `analyst`, `casual`, `club_fan`, `player_focus`.
- Languages: `en`, `es`, `pt`, `fr`, `ar`. Arabic renders right to left.
- The UI meets WCAG 2.1 AA contrast, works by keyboard, and stays usable down to 375 px wide.

## Constraints

| Area | Rule |
|---|---|
| Budget | Azure for Students ($100 credit). Budget alerts at $25 and $50. Mini model deployments by default. |
| Stack | Python 3.12 + uv, FastAPI, SQLAlchemy, NumPy/pandas; React + Vite + TypeScript + Tailwind. |
| Data units | Pitch 105 × 68 m, origin at bottom-left, attacking left to right in period 1; tracking at 10 Hz; time in seconds from kickoff of each period. |
| Submission | Public GitHub repo, demo video under 2 minutes, English materials, working test URL with instructions. |

## Governance

- **Amendments:** edit this file in a commit prefixed `CONSTITUTION:`, bump the version (major = principle removed or redefined, minor = principle added, patch = wording), and note the reason in the commit body.
- **Compliance:** every self-review and code review checks changes against Principles I–XI. Any exception is written down in the PR with its reason.
- **Precedence:** Hackathon Official Rules > this constitution > implementation plan > `TASKS.md` > individual commits.
